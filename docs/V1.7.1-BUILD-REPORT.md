## 1. Open on Command when ARC mode is on

There is one change, in `boot()` only. After `selectDomain(0); render();` the new line is `if(arcCfg().enabled)switchView('dash');`.

- `selectDomain(0)` stays, so the Domains panel is still primed underneath (asserted).
- The `switchView('dash')` call runs `maybeShowWelcome()` straight away. At that moment the corpus hasn't loaded, so `arcLive()` is false and the function returns **without** touching `lastWelcomeSeen`. The card then comes from the existing corpus-load callback (`renderArcDash(); maybeShowWelcome();`). The `.then` always runs after `boot()` returns, so ordering is not a race.
- The once-a-day throttle (`state.lastWelcomeSeen === today()`) is untouched and still the only gate. A same-day reload lands on Command with **no** second card (asserted).
- **ARC off:** no switch, so the app opens on Domains exactly as in v1.7.0 (asserted).
- **First-ever visit:** unchanged. The explainer comes first, then What's New. `ARC_FIRST_EVER_VISIT` still suppresses the card.

## 4. Judgment calls

1. **Where the switch sits.** It goes right after `selectDomain(0); render();` as the brief says, which is before `ARC_FIRST_EVER_VISIT` is computed. That is safe because the immediate `maybeShowWelcome()` exits on `!arcLive()` before it reads that flag.
2. **"sign" → "approve".** The brief's suggested wording used "sign off with their own private key". Both reviewers in round 1 (H and C) objected that "sign" would then appear only in the two Non-repudiation items. The private key, bound to one person, still carries the concept.
3. **Hint edit kept to one word.** The v1.7.0 audit showed that risk-hint rewrites echoing step wording draw HIGH ratings. Replacing "controls" with "response" fixed the contradiction without adding step vocabulary.
4. **Lesson prose not touched.** The `d1_4` reading still says "Apply it, then verify it actually works" in its paragraph about controls. It is not step text and the brief scoped the change to step text, so it is left as a note.
5. **Local test setup only.** The pinned browser in this environment matched Playwright 1.63.0, so it was installed with `--no-save`. `package.json` and the lockfile were left unchanged.
